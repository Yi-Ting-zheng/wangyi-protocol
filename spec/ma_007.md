# MA-007 — Dual-Condition Mathlib Verification Gate

> **Protocol:** Wangyi Protocol v2.0-draft　**Type:** BLOCKING verdict gate
> **Truth level:** `DEFINITION` (rule text); gate effects are `EMPIRICAL`.
> **Origin incident:** audit of a ~121,700-file AI-generated formal corpus
> whose "zero textual `sorry`" proved to be an escape artifact.

## 1. Motivation

Text-level `sorry` scanning fails against corpora built from
**project-internal redefinition + facade imports + internal import chains**:
the core objects are redefined locally, proofs are real but about the local
objects, the entry file imports the native library once as a facade, and the
textual `sorry` count is zero while semantic verification never happened.
MA-007 makes the verdict depend on the transitive closure and the axiom
chain, never on text counts.

## 2. The dual condition

The verdict `MATHLIB_VERIFIED_COMPLETE` MAY be issued iff **both**:

### Condition A — import-tree coverage

1. Traverse the main theorem's **transitive** import closure (not the entry
   file).
2. The closure MUST reach the native library (`Mathlib.*` or successor).
3. **Core-object redefinition check**: for each core mathematical object
   category (polynomials, finite fields, hypergraphs, matrices, modules,
   ideals, …):
   - *Derived alias* over an imported native type
     (`abbrev P := MvPolynomial (Fin n) ℂ` where `MvPolynomial` is imported)
     → LOW risk, permitted;
   - *Parallel redefinition* (`structure`/`class`/`inductive` shadowing a
     native name, or a definition in a file with zero native imports) →
     **HIGH risk, BLOCK**.
4. **Bloat signal**: closure > 200 internal modules → flag
   `CLOSURE_BLOAT_SUSPECT` and register in the report (warning).

### Condition B — full-chain sorryAx scan

1. Run `#print axioms <main-decl>` over the full dependency chain.
2. The axiom set MUST contain ZERO `sorryAx`.
3. **Error ≠ PASS (R07)**: toolchain error output (`unknown identifier`,
   missing olean, compile failure, non-zero exit) maps to `UNVERIFIABLE`,
   NEVER to `PASS`. (A short declaration name missing its namespace prefix
   is a known false-PASS generator and MUST be rejected this way.)
4. **Unverifiable ≠ PASS**: an external corpus that cannot be compiled in a
   pinned toolchain leaves condition B `UNVERIFIABLE` forever; the overall
   verdict is then `INCONCLUSIVE`, never `PASS`.

## 3. Verdict table

| Condition A | Condition B | Verdict |
|-------------|-------------|---------|
| PASS | PASS | `MATHLIB_VERIFIED_COMPLETE` |
| PASS | UNVERIFIABLE | `INCONCLUSIVE` |
| FAIL | any | `BLOCK_条件A` |
| any | FAIL_SORRYAX | `BLOCK_条件B` |
| FAIL | UNVERIFIABLE | `BLOCK双重失败` |

# MA-009 — 通道保真度门（Channel Fidelity Gate）

> **Protocol:** Wangyi Protocol v2.0-draft　**Type:** BLOCKING verdict gate
> **Truth level:** `DEFINITION`（规则文本）；门控效果 `EMPIRICAL`
> **适用场景：** Chat ↔ Agent 中转压缩通道 与 Skill 分身直连通道的分流与隔离
> **设计动因：** 中转压缩会破坏源码字符、行号锚点、声明边界、报错栈等高精度元信息，导致指令衰减、假阳性、行号错位。

## 1. 核心原则

### 1.1 保真度优先原则
高层骨架设计必须走**无压缩直连**通道；底层批量 IO 可走中转通道，但**不得将压缩摘要反向污染骨架设计层**。

### 1.2 通道定义
- **C-Direct（分身直连，无压缩）：** Skill 分身直接接收原始完整上下文，不做中间摘要压缩。
- **C-Proxy（Agent 中转，有损）：** Chat ↔ Agent 间接传递，存在截断、摘要、压缩、上下文裁剪。

### 1.3 保真度非对称原则
压缩信息**只允许下流**（低保真度通道产出不得作为高保真度通道的输入），**禁止上流**（C-Proxy 的压缩摘要不得反向注入 C-Direct 的骨架设计上下文）。

## 2. 任务分流铁律（强制）

| 任务类型 | 强制通道 | 理由 |
|---|---|---|
| **顶层骨架、公理定义、证明结构设计**（Lean/Coq 公理、定理骨架、声明边界） | **C-Direct** | 需保留完整声明、行号、符号精确性 |
| **形式化审计、语义校验（WP-L1/L2/L3）** | **C-Direct** | 需逐字符比对原始源码 |
| **沙盒批量扫描、文件读取、编译探针、日志抓取** | **C-Proxy**（可接受） | 批量 IO、脏活，精度要求低于骨架设计 |
| **数值结果、统计汇总、进度报告** | **C-Proxy**（可接受） | 最终结论可用摘要形式回传 |
| **对抗性搜索、反例枚举** | **C-Proxy**（可接受） | 结果导向任务 |

> **注：** 模糊边界时一律走 **C-Direct**（保守原则）。

## 3. 强制校验要素（MA-009.1）

凡通过 **C-Proxy** 通道回传的结果，必须附带以下**不可省略**字段：

| 字段 | 类型 | 要求 |
|---|---|---|
| `source_hash` | `string`（hex, 64） | 原始文件的 SHA-256。若涉及多文件，须列出主文件 hash 并附 `source_hash_list` |
| `line_range` | `object` 或 `string` | 涉及行号范围（`start:end`），精确到受影响行 |
| `artifact_id` | `string` | 对应被审计声明/文件的稳定 ID（同 MA-008 定义） |
| `channel_id` | `enum` | `direct` / `proxy`，标识实际传递通道 |
| `context_preserved` | `boolean` | 是否保留原始上下文完整性（C-Direct 必须为 `true`） |

## 4. 逐字符比对门（MA-009.2）

1. **独立校验：** 接收端（Chat/分身）须独立读取 `source_hash` 指定的原始文件对应 `line_range` 行。
2. **逐字符比对：** 将读取到的原始文本与 Agent 回传文本逐字符比对（至少比对关键字段：声明、行号锚点、报错栈、符号序列）。
3. **不一致判定：** 出现任何不一致 → 判定 `CHANNEL_DEGRADED`（**BLOCKING**），禁止直接采信该回传结果。
4. **强制重传：** 触发 `CHANNEL_DEGRADED` 时，必须改走 **C-Direct** 通道重新回传原始完整内容。

> **目标：** 防止中转压缩层带来隐性失真（典型案例：`$nlexample` 插值假阳性）。

## 5. 指令衰减防御（MA-009.3）

- **严格服从模式（strict compliance mode）：** 审计类任务下发时，硬性契约（如"禁止思考"、"直接写台账"、"不得改写主文件"）必须以**不可覆盖**方式注入（system-level 注入），不得被 Agent 内部 system prompt / CoT 覆盖。
- **禁止自主优化：** Agent 不得对下发指令做改写、扩展、"改进"。仅允许按字面严格执行。
- **禁止自作主张总结：** 回传时优先搬运原始证据（日志、栈、源码片段），而非仅回传 Agent 自行总结后的精简版。若必须摘要，须同时附带**原始片段**（满足 §3 字段）。
- **CoT 隔离：** Agent 的思考过程不得混入最终回传的"原始证据"字段中。用户可见的原始证据字段必须与推理链物理隔离。

## 6. 累积压缩防御（MA-009.4）

为防止多轮对话中压缩失真累积：

1. **保真度预算（fidelity budget）：** 每轮对话追踪当前上下文的保真度估计值 $F_t \in (0,1]$。
2. **基线：** 从原始文件新读取时 $F_t \leftarrow 1.0$。
3. **衰减：** 每次基于 C-Proxy 压缩上下文继续推理时，按压缩率施加衰减：$F_{t+1} \leftarrow F_t \cdot (1 - \delta)$，其中 $\delta \ge 0$ 为中转压缩导致的保真度损失（工程参数，至少记录）。
4. **强制刷新：** 当 $F_t < F_{min}$ 时（推荐 $F_{min}=0.8$），**禁止**继续基于压缩后的上下文推理。必须强制从原始文件重新读取（刷新至 $F=1.0$），改走 C-Direct 通道。
5. **审计留存：** 每轮更新 $F_t$、通道、触发原因须写入审计日志（可关联 MA-008 的 `provenance` 阶段记录）。

## 7. 双向隔离（MA-009.5）

- **单向流动：** C-Proxy 产出（压缩摘要）**不得上行**至 C-Direct 骨架设计上下文。
- **房间隔离：** 高保真房间（形式化骨架 WP-L1/L2/L3 相关）与低保真房间（批量 IO）之间的边界须强制隔离。
- **污染检测：** 若检测到压缩摘要被注入高保真上下文 → 判定 `CHANNEL_CONTAMINATION`（**BLOCKING**），立即回滚该注入并强制走 C-Direct。

## 8. 审计判定

| 判定码 | 等级 | 含义 | 处理 |
|---|---|---|---|
| `PASS_MA009` | 合格 | 通道选择正确，校验通过，隔离未破坏 | 通过 |
| `CHANNEL_DEGRADED` | **BLOCKING** | C-Proxy 回传与原始文件比对不一致（§4） | 禁采信，强制 C-Direct 重传 |
| `CHANNEL_MISROUTED` | **BLOCKING** | 高保真任务错误走 C-Proxy（违反 §2） | 修正通道后重执行 |
| `CHANNEL_CONTAMINATION` | **BLOCKING** | 压缩摘要反向污染高保真上下文（§7） | 回滚并隔离 |
| `PROVENANCE_INCOMPLETE` | WARNING | 缺失 §3 强制字段（`source_hash`/`line_range` 等） | 要求补全，不直接 block（但阻止后续严格校验） |

## 9. 与既有规范整合

- **MA-008（Per-Declaration Provenance）：** `channel_id`、`source_hash`、`line_range` 可并入 provenance 阶段记录（`execution_environment` 已覆盖生成环境；通道选择宜补充到阶段元数据）。
- **WP-L2（Semantics）：** 哈希校验与逐字符比对强化"语义锚点"保真度，防止压缩导致的声明边界错位。
- **R 系列（Meta-rules）：** 建议新增 `R14 反向污染禁令`、`R15 下行契约不可覆盖`、`R16 保真度预算 + 强制刷新`，与本门保持一致。

## 10. 工程参数（占位）

| 参数 | 推荐值 | 说明 |
|---|---|---|
| `F_MIN` | `0.8` | 强制刷新的保真度阈值（§6） |
| `DELTA_PROXY` | `0.05`～`0.10` | 每轮基于 C-Proxy 的衰减量 $\delta$（视压缩强度而定） |

> 参数为工程占位，首次落地后按实测失真率标定。

## 11. 附记：设计溯源

本门直接溯源于复盘结论：
> "Agent适合干底层IO、批量探针这类脏活，但不能让它中转传递高层数学证明骨架与原始源码元信息，中转压缩会悄悄破坏保真度；高层骨架设计必须走无压缩的分身直连链路。"

以及 P1 混合范式的务实精神：**不强行走纯统一归纳，改用可验证的有限段+解析闭合**——对应工程上：**不强行让所有信息都走同一有损通道，改用保真度分级通道 + 可验证的逐字符比对**。

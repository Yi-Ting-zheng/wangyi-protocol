> **性质**：MA-008 后续课题的独立登记处。此处条目在关闭前**不合并进主规范**的
> 阻断级语义；规范文本中的对应门（如 P9）以 `warn（挂起）` 过渡形态存在。
> **真值层级**：本文件为 `HYPOTHESIS` / 登记（计划性文本）；引用规范的
> `DEFINITION` 部分如实标注。

> **定位补充（2026-10-18，`DEFINITION` 级定位声明）：模型无关性。** 本
> 流水线的能力主张不在模型权重里，而在协议契约里：通用基座（GLM /
> DeepSeek / Qwen 等）只要能解析并按规范执行（IPTTT + 审计规则 + GAP

> 选型判据 = **协议兼容度测试**（能否读懂并执行本协议），而非专业数学
> 语料的预训练量。skill 分身（骨架设计 / 底层推演）与通用执行 Agent
> （机械化子任务）的权责边界按 AGENTS.md 铁律 S3 的 T-模式 / E-模式
> 切分。此为定位声明而非能力宣称——其可证伪形式：任何基座接入须先过
> 协议一致性对照（读懂判据文本、按台账纪律执行、机器核对出口闭合），

## TP-MA008-1 — P9 判决形态稳定化（执行环境门 strict 化）

| 字段 | 值 |
|---|---|
| 编号 | `TP-MA008-1` |
| 状态 | `OPEN`（登记于 2026-10-18） |
| 规范挂点 | `schema/provenance_schema.yaml` P9（`type: warn`，`suspended_promotion: true`）；`spec/ma_008.md` §5.4 / §8.2 / §9.1 |
| 前置完成 | schema v1.1 已落地：`execution_environment` 闭集枚举 + `cost_ledger_ref` 指针 + P9（warn）注册 |

### 1. 背景与动机

同一族模型在 **自有集群** 与 **外部 API** 两侧的生成条件不对等（服务端截断
上下文、限采样、不透明缓存、独立计量口径——内部侧甚至可绕过外部 token 计量
规则）。思考链是坐标变换后的表层叙事；`model_family` 同族不保证产出可比。
schema v1.1 因此新增生成条件轴（`execution_environment`）与成本账本指针
（`cost_ledger_ref`）。P9 当前仅作**披露通道**（warn-only），未阻断。

### 2. 本课题要回答的问题（判决形态本身）

P9 的"遮挡条件"如何落棒为可机器执行的 strict 判据，即三个开放子问题：

| # | 子问题 | 当前哪步还差实测 |
|---|---|---|
| 1 | **粒度判令**：混环境 stage 强制拆条——判 `BLOCK_字段不合规` 还是新裁决值？ | 缺真实清单上的混环境实例；判令方向未定 |
| 2 | **默认形态**：v1.1 清单缺 `execution_environment`——逐条 WARN 累计到阈值升 BLOCK，还是任一缺失即 BLOCK？反向举证门在环境轴上的强度需与 contribution_type 缺失（`BLOCK_粒度不足`）对齐测量 | 未在真实漂移场景测过 |
| 3 | **签名一致性判令**：external_api stage 签"权重哈希"——WARN 还是 BLOCK？该错位目前仅"错误粒度的身份"，阻断强度待定 | 缺四维对照（尤其逃逸向量） |

### 3. 关闭条件（promotion gate，全部满足方可并回主规范 strict）

1. **四维对照组通过**：T01 式阳性/阴性/边界/逃逸 ≥12 用例，P9 维全覆盖
   （含逃逸：伪造 `internal_cluster` 标签但账本指针指向外部计费切片的对账跳变）。
2. **真实清单暴露**：≥2 个真实项目清单完整跑一轮 P9 warn 通道，误报可归零
   （或如实登记为已知边界），漏报清单登记。
3. **双实现低成本**：判据表达为 schema 规则文本后，第二独立实现（或
   ma008_provenance.py 之外的复核器）可在一日内对齐——否则判据写得只有
   单实现能懂，即属"声明精度与实现精度不一致"的越权主张（CASE-02 型）。
4. **裁决值封闭性复核**：若需新增裁决值，先过主规范封闭枚举扩展程序
   （§5 schema 更新 + CHANGELOG + 裁决表同步），禁止实现侧私造。

### 4. 判假条件（对本课题自身的证伪）

- 若真实清单暴露显示 `execution_environment` 的**自报**在内部集群侧完全
  不可取证（无任何锚点），则该字段退化为纯宣誓——此时登记
  `TP-MA008-1-JUDGEMENT-REVOKED`，P9 维持 warn 永不 strict，并在
  GAP 登记处新开条目，不静默降级。
- 若发现环境字段90%以上场景恒为同一取值（无区分度），登记为
  "低区分度字段"，降级为可选披露，不入 strict。

### 5. 非目标（明确不做）

- ❌ 不把 token 消耗数字搬入溯源清单（自报量无对手方锚点；账本指针已够）。
- ❌ 不改动 P1–P8 既有判据与封闭裁决集的任何取值。
- ❌ 不做"环境可信度评分"——环境不携带可信度权重（溯源≠真值纪律不变）。
- ❌ 不要求对 `local_runtime` 与 `internal_cluster` 做进一步细分（前者
  按需在第二版本枚举扩展时再议）。

### 6. 关联

- **SiliconLifeOS EMF Profile**（独立研究树，不在本仓内，本仓不含代码）：
  参考实现 `ma008_provenance.py` 的 P9 字段落地与四维对照扩展在 EMF 侧
  另行登记执行（EMA 工单口径）。
- 算力链（2026-02 路线）：计费账本切片 id 格式待算力链侧给出台账条目
  规范后，在 `cost_ledger_ref` 注释中登记映射。
